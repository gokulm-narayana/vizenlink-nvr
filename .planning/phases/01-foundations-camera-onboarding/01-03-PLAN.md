<objective>
Store camera credentials at rest exactly as D-14 and D-29 decide: AES-256-GCM in SQLite with a random data key held in the OS keystore or an owner-only key file, a recorded key source/id and canary, and `nvr status` reporting whether credentials are decryptable.

Purpose: The add flow (01-09) seals the password before its single DB transaction (CAM-06), and the headless NVR must decrypt after a power cut with nobody present.
Output: secrets/{permissions,keysource,vault}.py, log redaction, status integration, at-rest tests.

Reversibility: D-14 is rated costly (changing the key-wrapping scheme later re-encrypts every stored credential). The `enc_version` and `key_id` columns written with every sealed secret keep that migration row-by-row.
</objective>

1. `permissions.py`: `ensure_private_dir` (mkdir parents, chmod 0o700 on POSIX), `ensure_private_file` (POSIX chmod 0o600; Windows: `subprocess.run(["icacls", str(path), "/inheritance:r", "/grant:r", f"{getpass.getuser()}:F"], shell=False, check=True, capture_output=True)`), `assert_private`.
2. `keysource.py` `FileKeySource`: path `<data_dir>/secrets/data.key`; `load(create=True)` creates the key with `os.open(path, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o600)` writing `os.urandom(32)`; existing file -> `assert_private` then read exactly 32 bytes (other length -> InsecureKeyFile("key file corrupt")). `load(create=False)` returns None when absent.

4. `runtime.py`: `open_runtime` calls `initialise_vault(rt)` after migrations and stores the result on `rt.vault_status`; it never raises on mismatch (status must still run).
5. `status.py`: add `credentials_status`, `key_source`, `key_id` fields from `rt.vault_status` (re-checked via check_canary).
6. Tests: `tests/integration/test_status_credentials.py` runs `nvr status --json` twice (credentials_status "ok", same key_id both times, key file mode 0o600 on POSIX); then overwrites data.key with 32 different bytes -> status reports "mismatch" and the canary row is unchanged; then deletes data.key -> "missing_key" and no new key file was created. `tests/unit/test_credentials_at_rest.py`: round trip; AAD binding (open with a different serial or username raises CredentialsUnreadable); two seals of the same password differ; empty and 32-character passwords round-trip; after sealing a sentinel password `Sentinel-Pa55word!` into a row of a throwaway table in the migrated DB, the raw bytes of nvr.db, nvr.db-wal and nvr.db-shm never contain the sentinel; POSIX: chmod the key file 0o644 -> insecure_key_file.
