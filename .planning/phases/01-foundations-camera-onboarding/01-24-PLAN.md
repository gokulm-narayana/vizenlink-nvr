  <context>D-11 (rated one-way in CONTEXT.md, chosen by Claude on the user's behalf) makes the serial (the camera's thing name, `getSerialNumber`) the primary key, with IP, port, MAC and TLS fingerprint as mutable attributes. Undoing it after Phase 2 lands means a data migration of every recording, event and API reference. `camera_api`'s CameraSecureStorage is also keyed by serial, and the mobile app identifies cameras the same way.</context>
  <options>
    <option id="serial-pk">
      <name>Serial as primary key (D-11 as written)</name>
      <pros>Matches camera_api and the mobile app; one identity everywhere; no join to translate ids; re-IP only updates attributes</pros>
      <cons>If a camera's serial could ever change (board swap, firmware bug), every referencing row must be rewritten</cons>
    </option>
    <option id="surrogate-id">
      <name>Integer surrogate id as primary key, serial UNIQUE NOT NULL</name>
      <pros>A serial change touches one column; foreign keys stay stable</pros>
      <cons>Diverges from D-11 and camera_api keying; every API and log needs both ids; more code in every query</cons>
    </option>
  </options>
