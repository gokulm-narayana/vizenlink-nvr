  <files>src/vizenlink_nvr/api/v1/auth.py, src/vizenlink_nvr/api/v1/cameras.py, tests/integration/test_media_auth_webhook.py, tests/integration/test_mediamtx_http_auth.py</files>
  <action>
1. Implement `POST /api/v1/cameras/{serial}/media-token` in `src/vizenlink_nvr/api/v1/cameras.py`:
   - Requires authenticated user.
   - Verifies viewer camera access via `verify_camera_access(serial, user)`.
   - Returns `{"token": token, "expires_in": 900, "stream": stream, "path": f"cam/{serial}/{stream}"}`.
2. Implement `POST /api/v1/auth/mediamtx` in `src/vizenlink_nvr/api/v1/auth.py`:
   - Parses MediaMTX payload: `ip`, `user`, `password`, `path`, `protocol`, `action`, `query`.
   - Case 1: `action == "api"` -> verify `user == "nvr-control"` and matching control secret from loopback IP. If match, return 200 OK.
   - Case 2: `action == "read"` -> parse query string for `token=...`. Verify token via `MediaTokenService`.
   - Verify token path matches requested `path` (`cam/{token.serial}/{token.stream}`).
   - Verify user exists, is active, and still has permission to view that camera.
   - Return 200 OK on success; return 401/403 on failure.
   - Case 3: all other actions (`publish`, etc.) from external clients -> return 403 Forbidden.
3. Author `tests/integration/test_media_auth_webhook.py` simulating MediaMTX webhook payloads:
   - Valid token -> 200 OK.
   - Missing token -> 401 Unauthorized.
   - Expired token -> 401 Unauthorized.
   - Tampered token -> 401 Unauthorized.
   - Viewer requesting restricted camera stream -> 403 Forbidden.
   - Internal API control action from loopback -> 200 OK.
4. Author `tests/integration/test_mediamtx_http_auth.py` verifying the full handshake.
