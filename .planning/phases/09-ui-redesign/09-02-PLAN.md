    - A viewer without CAM1 in permissions: 403, and upstream is never called.
    - Stream other than main or sub, a serial containing `..`, `/` or characters outside `[A-Za-z0-9._-]`, or a session id outside `[A-Za-z0-9-]`: rejected (404 or 422), and upstream is never called.

    - Body over 64 KiB: 413, and upstream is never called.
    - Upstream connection refused or timeout: 502 JSON `{"detail": "Live video service unavailable"}`.
    - PATCH and DELETE on `/cam/CAM1/sub/whep/{session_id}` forward to the same upstream path; PATCH forwards `If-Match` and the `application/trickle-ice-sdpfrag` body.

Create `src/vizenlink_nvr/api/cam_proxy.py` exporting `cam_proxy_router`, an `APIRouter` whose routes use `include_in_schema=False` (media plumbing, not part of the documented `/api/v1` contract, so the OpenAPI baseline does not change for D-14).

Three routes:
- POST `/cam/{serial}/{stream}/whep`
- PATCH `/cam/{serial}/{stream}/whep/{session_id}`
- DELETE `/cam/{serial}/{stream}/whep/{session_id}`

Validate path params with FastAPI `Path(pattern=...)`: serial `^[A-Za-z0-9._-]{1,64}$`, additionally rejecting `.` and `..`; stream `Literal["main", "sub"]`; session_id `^[A-Za-z0-9-]{1,128}$`. Each route depends on `CurrentUser` and calls `verify_camera_access(serial, user)` before any network I/O.

Build the upstream URL only from validated parts: `http://127.0.0.1:{port}/cam/{serial}/{stream}/whep[/{session_id}]`. Use the port from `request.app.state.mediamtx_webrtc_port` when set, else `MediaMtxPorts().webrtc`. Forward only the `token` query parameter, if present.

Read the body with a 65536-byte cap: reject first on a Content-Length header over the cap, then on the actual length; both return 413. Forward only the request headers Content-Type and If-Match.

Call upstream with `httpx.AsyncClient(timeout=10.0, transport=getattr(request.app.state, "cam_proxy_transport", None))`. The transport attribute is the test seam; production leaves it unset. Map `httpx.ConnectError`, `httpx.TimeoutException` and other `httpx.TransportError` to 502 with the JSON detail above.

Return a `Response` carrying the upstream status code and body, and only these response headers when present: Content-Type, Location, ETag, Accept-Patch, Link. MediaMTX's Location is a path under `/cam/...`, which stays valid on the NVR origin, so pass it through unchanged. Log nothing that contains the token or the SDP.

Register the router in `create_app` with `app.include_router(cam_proxy_router)` right after `app.include_router(v1_router)`, which is before the SPA mount, plus its import at the top with the other router imports. Do not touch the lifespan code.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN browser to FastAPI `/cam/*` | Untrusted path, query and body cross into a server-side HTTP client |
| FastAPI to loopback MediaMTX | The server makes outbound requests on behalf of the user |
| Unauthenticated caller to `/auth/status` | Status is public by design (boot routing) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-03 | Spoofing / Elevation | `/cam` proxy | high | mitigate | `CurrentUser` session or bearer required, plus `verify_camera_access` before any upstream call; MediaMTX still validates the media token through the auth webhook (defense in depth); tests cover 401 and 403 with the upstream untouched |
| T-09-04 | Tampering (SSRF / path traversal) | `/cam` upstream URL construction | high | mitigate | Host fixed to 127.0.0.1 and the configured WebRTC port; the path is built only from regex-validated serial, a two-value stream literal and a validated session id; only the `token` query parameter is forwarded; tests send `..`, encoded slashes and bad streams |
| T-09-05 | Information disclosure | Forwarded headers and logs | medium | mitigate | Header allowlist (Content-Type, If-Match) strips Cookie and Authorization; response header allowlist; no logging of token or SDP |
| T-09-06 | Denial of service | `/cam` request handling | medium | mitigate | 64 KiB body cap (413), 10 s upstream timeout, 502 on upstream failure |
| T-09-07 | Information disclosure | `site_timezone` on `/auth/status` | low | mitigate | Returned only when a session is authenticated; null otherwise |
| T-09-60 | Information disclosure | Accidental staging of the owner's `api/app.py` hunk or parallel executors' files | medium | mitigate | Private-index commits with a `git diff --cached --name-only` assertion before each commit; the owner's lifespan hunk is checked to remain unstaged |
</threat_model>
