Facts verified while planning:
- `POST /api/v1/cameras/{serial}/media-token?stream=main|sub` returns `{token, expires_in, stream, path}`, where `path` is `cam/{serial}/{stream}`.
- The MediaMTX auth webhook compares the request path with that token path exactly, including case. So the player must build the WHEP URL from the returned `path` and must NOT lower-case the serial. (Research Pitfall 9 suggested lower-casing, but that would fail the webhook check.)
- The reconciler names MediaMTX paths with a lower-cased serial. For serials containing uppercase letters, Live therefore fails today whichever casing the player uses. This is a pre-existing backend mismatch flagged to the owner (see 09-09 SUMMARY note). Do not change backend code here.
- MediaMTX's WebRTC listeners bind 127.0.0.1 only. Through the proxy, signaling works from any LAN browser, but media (ICE) succeeds only from a browser on the NVR host. Record this as a known limitation in the SUMMARY; it is not a Phase 9 change.
- Only this plan edits `features/live/`, `services/player.ts` and the three legacy files above. Do not edit `lib/queries.ts`, the shell or shared components; read them.
</context>

  <behavior>
    - `start()` POSTs the media token request, then POSTs SDP to `"/" + path + "/whep?token=" + encodeURIComponent(token)` (for example `/cam/CAM1/sub/whep?token=...`), keeping the path's case.
    - `RTCPeerConnection` is constructed with an empty `iceServers` array.
    - Calling `cleanup()` while the token fetch is pending means no `RTCPeerConnection` is ever constructed. Calling it after the WHEP answer closes the peer connection and sends one `DELETE` to the WHEP `Location`. After cleanup no timer fires.
    - When WHEP fails, the connection state goes to failed or disconnected, or a stall lasts more than 5 s, the state becomes `reconnecting` and a restart is scheduled after 1 s, then 2, 4, 8, 16, and then 30 s repeatedly. Reaching `live` resets the backoff.
    - After 3 consecutive failed attempts the state is `offline` while retries continue at the capped interval.
    - `switchStream("main")` restarts with a new token for the main stream.
    - `retryNow()` cancels the pending backoff and restarts immediately (the tile's "Retry stream").
  </behavior>
  <action>
Modify `src/services/player.ts` in place. Keep the class API (`attach`, `switchStream`, `restart`, `cleanup`, `getState`) and add `retryNow`. Add `reconnecting` to `PlayerState`.

1. Add a monotonically increasing attempt generation and a `disposed` flag. Check both after every await in `start()`. If the attempt is stale or disposed, close anything it created and return.
2. Parse the media-token JSON into `{ token, path }` and build the WHEP URL from `path` as in the behavior block.
3. Construct the peer connection with no ICE servers (LAN-only; the public Google STUN host is removed).
4. Store the WHEP `Location` response header. In `cleanup()`, fire-and-forget a `DELETE` to it (same origin, ignoring errors), clear the stall watchdog and any reconnect timer, and set `disposed`.
5. Implement the reconnect scheduler with the backoff sequence, failure counter and `offline` threshold from the behavior block. A stall longer than 5 s while live counts as a failure.

Keep the logic framework-free (no React imports, no colour), as research noted.
