Data facts: `GET /api/v1/playback/timeline` returns `{segments[{id,start_time,end_time,is_protected,duration_seconds}], outages[{id,started_at,ended_at,duration_seconds,reason}], events[{id,event_type,start_time,end_time,is_locked}]}`. There is no explicit "removed by retention" span.

Planner derivation, recorded for the owner: inside the visible window, the interval earlier than `now - retention_days` (from `/api/v1/recording/status` for the camera) that has no segment is rendered as "removed by retention". When `retention_days` is null (size-based retention), no retention span is drawn and such gaps render as plain background. Outages always render as hatched warning.

Only this plan edits `features/playback/timeline/`, `lib/timeline.ts` and the two legacy files above. The Playback page itself is rebuilt in 09-11.
</context>
