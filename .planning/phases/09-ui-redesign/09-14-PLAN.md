Data facts:
- `GET /api/v1/health` returns `{status, db_ok, mediamtx_ok, storage_ok, total_cameras, active_cameras, details}`.
- `GET /api/v1/storage/status` returns `{storage_path, allow_system_disk, reserve_bytes, health_state, health_reason, telemetry{total_bytes,used_bytes,free_bytes,reserve_bytes}, estimated_retention_days}`.
- `GET /api/v1/health/outages?limit=50` returns `[{id,camera_serial,started_at,ended_at,duration_seconds,reason}]`.
- `CameraView` has no online flag. Treat a camera with an open outage (`ended_at` null) as Offline, with Last seen equal to that outage's `started_at`; otherwise it is Online.
- Recording uses the same active-mode definition as the RecorderStatusChip.
- Alert dismissal uses the store's session-only `dismissedAlertIds` (shared with the AlertStack).

Only this plan edits `features/dashboard/` and the two legacy files. Shared hooks (`useHealth`, `useAlerts`, `useCameras`, `useRecordingStatus`), `StatusBadge` and `InlineError` are read-only here.
</context>
