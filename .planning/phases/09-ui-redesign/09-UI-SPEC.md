# Phase 9 — UI Design Contract

> Visual and interaction contract for the UI Redesign phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Revision 2 applies the locked decisions D-01 to D-13 from `09-CONTEXT.md` on top of revision 1 and closes the four open items from the revision 1 sign-off. Where CONTEXT.md and revision 1 differed (accent, grounds, logo, added pages), CONTEXT.md won.

shadcn naming caveat for the executor: shadcn's `--primary` is this contract's brand **Accent fill**. `--primary-text` (added) is the accent shade used for text, links and icons on surfaces; in light mode it equals `--primary`, in dark mode it is lighter for AA. shadcn's `--accent` is only the neutral hover surface (the mobile "mid" ground). The selected state (active nav, selected row) uses the added `--selected` token.

## Spacing Scale

Declared values (multiples of 4). Tailwind default 4 px unit; use only these steps.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inner padding, tile grid gap on 4x4 |
| sm | 8px | Compact element spacing, tile grid gap, toolbar item gap, logo mark-to-wordmark gap |
| md | 16px | Default element spacing, card padding, form field gap, mobile page padding |
| lg | 24px | Section padding, desktop page padding, card-to-card gap |
| xl | 32px | Layout gaps between page sections |
| 2xl | 48px | Empty-state vertical padding, major section breaks |
| 3xl | 64px | Collapsed sidebar width, auth page top offset |

Fixed layout dimensions (all multiples of 4): top bar 56, sidebar 240 expanded / 64 collapsed, control height 36 default / 32 compact / 40 large, table row 40, list row 48, timeline canvas 120 plus 32 axis, dialog max width 480 (export 560, preview 960), content max width 1280 (Dashboard, Gallery, Cameras, Devices, Users, Profile; Live and Playback are full-bleed with 8 px padding), Add-camera card width 560, Stepper height 48, logo heights 12 (wordmark), 32 (mark), 120 / 80 (auth full lockup).

Exceptions (stroke, indicator and corner values, not spacing): 1 px borders; 2 px focus ring plus 4 px offset (the offset is a gap between element and ring, measured on the same 4 px scale); 2 px timeline cursor and playhead line; 2 px top-bar refetch progress line; 6 px control corner radius. Every other decorative mark is rounded to the 4 px scale (sidebar active indicator 4 px, recorded-footage span radius 4 px, locked-range underline 4 px, export-range handles 4 px wide). On `@media (pointer: coarse)` every interactive control gets a minimum 44 px hit area (`min-h-11 min-w-11`, which is a multiple of 4). Icon sizes 16 / 20 / 24 px. No other off-scale values; no arbitrary `p-[13px]` style classes.

## Typography

Exactly four sizes and two weights. Tailwind mapping: `text-xs` 12, `text-sm` 14, `text-xl` 20, `text-[28px]` defined once as `--text-display`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Body strong (card titles, table header cells, nav item labels, buttons) | 14px | 600 (semibold) | 1.5 |
| Caption (helper text, timestamps, tile meta, axis ticks) | 12px | 400 | 1.5 |
| Label (form labels, badges, overlay chips, tab triggers) | 12px | 600 | 1.4 |
| Heading (page title h1, dialog title, section h2) | 20px | 600 | 1.2 |
| Display (dashboard metric values only) | 28px | 600 | 1.2 |

Rules: no weight other than 400 and 600 (no 500, no 700, no `font-bold`). No ALL-CAPS labels except the 3-letter `REC` and `LIVE` chips. Canvas text on the timeline uses 12 px Inter, tabular figures, color from `--muted-foreground`. The logo images carry their own lettering and are exempt from the type scale.

### Auth routing and first run

Resolved behavior (this closes the open first-run item). The app boots by calling `GET /api/v1/auth/status` once (query key `authStatus`, no cache on boot) and routes by its `initialized` and `authenticated` fields.

| # | Condition | Requested path | Result |
|---|-----------|----------------|--------|
| 1 | status loading | any | Full-page skeleton (auth-width card shape under the full lockup), never the login form or the shell, so there is no flash of the wrong page |
| 2 | status request fails (network or 5xx) | any | Full-page error with the "NVR unreachable" copy and "Retry connection"; no redirect |
| 3 | `initialized=false` | any, including `/login` | `replace` to `/setup` |
| 4 | `initialized=true`, `authenticated=false` | `/login` | Stay |
| 5 | `initialized=true`, `authenticated=false` | `/setup` | `replace` to `/login` |
| 6 | `initialized=true`, `authenticated=false` | any other path | `replace` to `/login?next=<encodeURIComponent(pathname + search)>` |
| 7 | sign-in succeeds | `next` is valid | `navigate(next, { replace: true })` |
| 8 | sign-in succeeds | `next` missing or invalid | `navigate("/", { replace: true })` |
| 9 | setup succeeds (the API response sets the session cookie) | n/a | invalidate `authStatus`, `navigate("/", { replace: true })`; no second sign-in |
| 10 | `authenticated=true` | `/login` or `/setup` | `replace` to `/` |
| 11 | any API call returns 401 while signed in | any | Clear the TanStack Query cache, go to `/login?next=<current path>` with an informational `role="status"` Alert "Your session ended. Sign in again to continue." |
| 12 | sign out (server succeeds or fails) | any | Clear local auth state, go to `/login` (no `next`); on server failure the sign-out error Alert (row in Copywriting) shows above the form |

`next` is valid only if it starts with a single `/`, does not start with `//`, contains no backslash, and does not start with `/login`, `/setup` or `/api`. Anything else is ignored.

Required e2e tests (Playwright; each is a pass/fail check): (a) fresh database, open `/playback?camera=X`: lands on `/setup`, submit setup, lands on `/` signed in; (b) initialized, signed out, open `/playback?camera=X&t=T`: lands on `/login?next=%2Fplayback%3Fcamera%3DX%26t%3DT`, sign in, URL equals `/playback?camera=X&t=T`; (c) signed out, open `/login?next=%2F%2Fevil.example`: after sign-in lands on `/`; (d) signed in, open `/login`: lands on `/`; (e) sign out: lands on `/login` with no `next`.

### Add camera `/cameras/add` (operator, owner)

Backend facts (read from `api/v1/cameras.py`): the wizard submits `POST /api/v1/cameras` (`RequireOperator`, so Operator or Owner; a Viewer reaching the URL gets the 403 state). Required fields are `serial` and `host`; everything else has an API default. The API inserts a registry record: it does not probe the camera, fetch its identity or read its TLS fingerprint (the CLI `nvr cameras add` does all of that through the onboarding service). Response is `201` with `CameraView` (`serial`, `host`, `name`, `state`, `last_error`, `streams`, ...). Duplicate serial returns `409` "Camera with serial '{serial}' already exists". Note the API's own default password is `admin123`; the UI never uses it: the password field is required and starts empty.

Discovery: the backend has NO discovery or scan endpoint (D-09; `grep discover` over `src/vizenlink_nvr/api` finds nothing), so this wizard is manual entry only. The page says so in plain words (see Copywriting) and points to `nvr cameras scan` on the NVR host. Web-based LAN discovery would be a new backend capability and is an owner decision, not built in this phase (Deferred).

### Users `/users` (owner)

Backend facts (read from `api/v1/users.py`, all `RequireOwner`): `GET /users` returns `id, username, role, is_active, created_at, updated_at, permissions[]` (camera serials) per user; `POST /users` takes `username` (min 1), `password` (min 8), `role` (`viewer` | `operator` | `owner`, default `viewer`), `permissions[]`; `PATCH /users/{id}` takes `role`, `is_active`, `permissions`; `POST /users/{id}/reset-password` takes `new_password` (min 8). Disabling a user or resetting a password signs that user out everywhere. The API rejects an owner disabling or demoting themselves (400). Duplicate username returns 409; unknown camera serials return 400.

## Interaction and Motion Contract

- Transitions 150 ms ease-out for color / opacity / transform on hover, focus, tooltip; 200 ms for sheet / dialog / sidebar width. Nothing else animates. All animation including the REC pulse and skeleton shimmer is removed under `prefers-reduced-motion: reduce`.
- Hover affordances use `--accent` (the neutral "mid" surface); pressed state uses `--primary-hover` for primary buttons and shadcn defaults elsewhere. Disabled controls: 50% opacity, `cursor-not-allowed`, still announced via `aria-disabled` when a tooltip explains why.
- Focus: visible 2 px `--ring` ring with 4 px offset on every focusable element; never `outline: none` without a replacement. Dialog / sheet / alert-dialog trap focus and restore it to the trigger (Radix defaults).
- Skip link "Skip to main content" is the first focusable element. Landmarks: `nav aria-label="Primary"`, `header`, `main#main`, `aside` for the camera list.
- Keyboard shortcuts (documented in tooltips with `kbd`): `G` then `L/P/E/G/D` jump to Live / Playback / Events / Gallery / Dashboard; Esc closes maximized tile, sheet and dialogs; `[` toggles sidebar. Shortcuts are disabled while typing in a field.
- Toasts (sonner) are for transient success only: snapshot saved, clip exported, settings saved, code copied, camera added, user created, access saved, password changed or reset. Anything needing action stays inline.
- Forms with secrets (login, setup, wizard password, create user, reset password, change password): `PasswordField` toggles are per field and reset to hidden when the dialog closes; values are never written to `localStorage`, query keys, logs or the URL; the TanStack Query mutation cache does not retain variables for these mutations (`gcTime: 0`).
- Data refresh never blanks a screen: TanStack Query keeps previous data and shows a 2 px top-bar progress line while refetching in the background.
- Timestamps display in the site IANA time zone (project rule), 24 h or locale per browser, with the zone abbreviation shown on Playback and Events detail; relative times ("3 min ago") carry the absolute time in `title`.
