# Phase 9 — UI Design Contract

> Visual and interaction contract for the UI Redesign phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: presentation and web stack only. Backend `/api/v1` contracts, `camera_api` semantics, polling cadences and the "never miss footage" core value are untouched. No new endpoints, no new product features.

## Source Map and Assumptions

Locked upstream (not re-asked): CLAUDE.md stack (Tailwind v4 + `@tailwindcss/vite`, shadcn/ui, TanStack Query, Zustand, React Router 8, lucide-react, custom canvas timeline, WHEP + hls.js), ROADMAP Phase 9 goal (light/dark tokens, sidebar shell + router, restyled pages, React 19 / Vite 8 / TS ~6.0, fix the Settings/Devices nav build break), STATE decisions D-45 (Simple/Advanced toggle, grid layout in `localStorage`, sub-stream tiles that switch to main when maximized), D-53 (24 h timeline), role names from `api/dependencies.py` (`viewer` < `operator` < `owner`; there is no `admin` role in code).

## Spacing Scale

Declared values (multiples of 4). Tailwind default 4 px unit; use only these steps.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inner padding, tile grid gap on 4x4 |
| sm | 8px | Compact element spacing, tile grid gap, toolbar item gap |
| md | 16px | Default element spacing, card padding, form field gap, mobile page padding |
| lg | 24px | Section padding, desktop page padding, card-to-card gap |
| xl | 32px | Layout gaps between page sections |
| 2xl | 48px | Empty-state vertical padding, major section breaks |
| 3xl | 64px | Collapsed sidebar width, auth page top offset |

Fixed layout dimensions (all multiples of 4): top bar 56, sidebar 240 expanded / 64 collapsed, control height 36 default / 32 compact / 40 large, table row 40, list row 48, timeline canvas 120 plus 32 axis, dialog max width 480 (export 560, preview 960), content max width 1280 (Dashboard, Gallery, Cameras, Devices; Live and Playback are full-bleed with 8 px padding).

Exceptions (stroke, indicator and corner values, not spacing): 1 px borders; 2 px focus ring plus 4 px offset (the offset is a gap between element and ring, measured on the same 4 px scale); 2 px timeline cursor and playhead line; 2 px top-bar refetch progress line; 6 px control corner radius. Every other decorative mark is rounded to the 4 px scale (sidebar active indicator 4 px, recorded-footage span radius 4 px, locked-range underline 4 px, export-range handles 4 px wide). On `@media (pointer: coarse)` every interactive control gets a minimum 44 px hit area (`min-h-11 min-w-11`, which is a multiple of 4). Icon sizes 16 / 20 / 24 px. No other off-scale values; no arbitrary `p-[13px]` style classes.

## Typography

Exactly four sizes and two weights. Tailwind mapping: `text-xs` 12, `text-sm` 14, `text-xl` 20, `text-[28px]` defined once as `--text-display`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Body strong (card titles, table header cells, nav item labels, buttons) | 14px | 600 (semibold) | 1.5 |
| Caption (helper text, timestamps, tile meta, axis ticks) | 12px | 400 | 1.5 |
| Label (form labels, badges, overlay chips, tab triggers) | 12px | 600 | 1.4 |
| Heading (page title h1, dialog title, section h2) | 20px | 600 | 1.2 |
| Display (dashboard metric values only) | 28px | 600 | 1.2 |

Rules: no weight other than 400 and 600 (no 500, no 700, no `font-bold`). No ALL-CAPS labels except the 3-letter `REC` and `LIVE` chips. Page title is one `h1` per route. Inputs are 14 px (accepted tradeoff: iOS Safari may zoom on focus; mobile web is secondary, A11). Canvas text on the timeline uses 12 px Inter, tabular figures, color from `--muted-foreground`.

## Color

Both themes are first-class. Tokens live in `src/styles/tokens.css` as CSS variables on `:root` and `.dark`, exposed to Tailwind through `@theme inline`. Components reference semantic tokens only. No hex literals in `.tsx` files; the single exception is the canvas token reader, which resolves tokens via `getComputedStyle` (re-read on theme change). Theme class is applied to `<html>` by an inline script in `index.html` before first paint to avoid a flash.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) `--background` | `#F5F7FA` | `#0F1217` | Page background, content canvas |
| Secondary (30%) `--card`, `--popover`, `--sidebar` | `#FFFFFF` | `#171B22` | Cards, sidebar, top bar, dialogs, popovers |
| Accent (10%) `--primary` | `#0056D2` | `#64B5F6` | See reserved list below |

| Destructive `--destructive` / `--destructive-foreground` | `#C62828` / `#FFFFFF` | `#C93A33` / `#FFFFFF` | Destructive buttons only |
| Foreground `--foreground` | `#14181F` | `#E6E9EF` | Body text |
| Muted text `--muted-foreground` | `#566070` | `#9AA3B2` | Secondary text, captions, offline state |
| Neutral surface `--secondary`, `--muted`, `--accent` (shadcn) | `#EEF1F5` | `#1F242D` | Hover, table stripes, skeletons, inactive chips |

| Video `--video-bg` / `--video-overlay` / `--video-fg` | `#000000` / `rgba(0,0,0,0.6)` / `#FFFFFF` | same | Tile and player surfaces in both themes |

Status badge fills use the status color at 12% alpha over the card, with the full-strength color for icon and text. A status is never conveyed by color alone: every badge carries an icon and a word (Online / Offline / Recording / Not recording / Degraded).

Verified contrast (WCAG 2.2, computed 2026-11-05): light foreground on background 16.6:1, muted text on card 6.4:1, accent on card 6.4:1, accent on selected 5.6:1, white on accent 6.4:1, white on destructive 5.6:1, success 5.0:1, warning 6.1:1, info 5.6:1, control border 3.5:1; dark foreground on card 14.2:1, muted text on card 6.8:1, accent on card 7.8:1, accent on selected 6.9:1, dark text on accent 8.5:1, white on destructive 5.1:1, critical 5.7:1, success 7.8:1, warning 9.6:1, info 9.3:1, control border on card 3.7:1. The executor must keep these pairings; any token change needs the same check.

Accent reserved for (exhaustive):
1. The single primary button of a view or dialog (Export clip, Pair mobile device, Sign in, Create owner account, Save changes)
2. Focus ring on every focusable element
3. Active sidebar item text/icon and its 4 px leading indicator (background is `--selected`)
4. Selected state of a toggle-group item and the selected day in the calendar
5. Timeline: recorded-footage spans and nothing else; playhead uses `--foreground`
6. Inline text links and the Unread events count badge
7. Switch / checkbox / slider / progress checked or filled portion, except the storage progress bar which uses success / warning / critical by threshold

Accent is never used for: card backgrounds, headings, icons in general, decorative borders, every button, hover states, or status.

Semantic color rules: `--destructive` fill is only for buttons and confirmations that delete or reset something. `--critical`, `--warning`, `--success`, `--info` are status colors, not decoration. Offline is neutral (`--muted-foreground` with `WifiOff` icon), not red; red is reserved for recording-critical conditions (storage critical, recorder degraded, destructive actions) so a quiet offline camera does not drown out a real failure.

Elevation: flat. Cards use 1 px `--border`, no shadow. Only popover, dropdown, dialog and sheet use `shadow-md`. No glows, no gradients, no `backdrop-blur` over video (GPU cost at 16 tiles; overlays are solid `--video-overlay`).

Radius: 6 px controls, 8 px cards / tiles / dialogs, 9999 px badges and dots.

## Page Contracts

Every page has all five states: loading (Skeleton in the final layout shape, never a bare "Loading..." string), empty (`empty` component with the matching Copywriting Contract row), error (inline `Alert` with the matching "Retry {action}" button from the Copywriting Contract), 403 (below) and populated.

Primary visual anchor per route (the one element the eye lands on first; all other elements are subordinate in size and contrast):

| Route | Anchor |
|-------|--------|
| `/setup`, `/login` | The centered auth `Card` and its single primary button |
| `/` Live | The video tile grid (a maximized tile when one is open) |
| `/playback` | The video area, with the timeline canvas as its direct companion |
| `/events` | The `EventCard` list (snapshot thumbnails lead each card) |
| `/gallery` | The thumbnail grid |
| `/dashboard` | The Recorder status `MetricCard`, first in Row 1 (its status word is the only Display-size value on the page; Cameras online and the other Row 1 cards are subordinate, with Heading-size values) |
| `/cameras`, `/cameras/:serial` | The settings form for the selected camera (the camera list is secondary) |
| `/devices` | The primary "Pair mobile device" button above the devices table |

### Setup wizard `/setup` and Login `/login`

Centered `Card`, 400 px wide (setup 480), vertically offset 64 px from the top on desktop, full-width minus 16 px padding on mobile; the wordmark sits above the card. Fields use `Field` with visible labels (never placeholder-only labels), password fields have a show/hide toggle (`Eye` / `EyeOff`, aria-label "Show password"). Setup keeps exactly the existing fields: Owner username, Password, Confirm password, Recording storage directory. Helper text under password: "At least 8 characters." Errors appear in an `Alert` inside the card (`role="alert"`) and the first invalid field receives focus. Submit buttons show a `Spinner` and are disabled while pending. Lockout error from the API (5 failures, 15 minutes) is shown verbatim in the Alert with the copy prefix in the Copywriting table.

### Live `/`

Toolbar (48 px, sticky): grid-size `toggle-group` (1x1, 2x2, 3x3, 4x4 — Simple view offers 1x1, 2x2, 3x3 only), page `pagination` (shown only when cameras exceed tiles per page), camera count caption ("12 cameras"). Grid: CSS grid, gap 8 (4 on 4x4), tiles 16:9, fill the remaining viewport height (`calc(100dvh - topbar - toolbar)`), page scrolls only when 16:9 tiles cannot fit. Below 768 px tiles per row = min(dimension, 2), below 480 = 1. The persisted dimension and page keys in `GridStorage` are unchanged.

Tile (`VideoTile`): black surface, radius 8, 1 px `--border`. Overlays use solid `--video-overlay` chips with `--video-fg` text:
- Top-left: camera name chip (Label style, truncates with ellipsis, title attribute carries full name).
- Top-right: state chip — `LIVE` (success dot), `Connecting…` (Spinner), `Reconnecting…`, `Offline` (WifiOff).
- Bottom-left: `REC` chip with 8 px `--rec` dot when recording (pulse 2 s, static under reduced motion). Not recording but online: no chip.
- Bottom-right (hover / focus-within / always on coarse pointers): icon buttons Snapshot (`Camera`), Mute (`Volume2`/`VolumeX`), Maximize (`Maximize2`), each 32 px, 44 px on coarse pointers, with Tooltip.
- Advanced view adds a bottom-centre caption chip: `SUB`/`MAIN`, protocol `WebRTC`/`HLS`, serial. Simple view hides it.

Tile states: connecting (Skeleton shimmer over black plus spinner), live, reconnecting (last frame stays, chip says Reconnecting…), offline (centered `WifiOff` 24 px + "Offline" + "Last seen {relative}" in Caption, no black void without text), error (centered message with "Retry stream" button). Maximize expands the tile to fill the content area inside the shell (not a modal): close with the `Minimize2` button or Esc; `F` toggles browser fullscreen; main stream is requested on maximize and sub stream restored on close, exactly as today. Players mount only for tiles on the visible page and unmount on route change.

Tiles are `role="group"` with `aria-label="{name}, {state}"` and are focusable; Enter maximizes.

### Playback `/playback`

Below: video area (black, 16:9, max height 60 dvh) with state overlays (Loading, "No footage at this time" in gaps, error with "Retry playback" button); `TransportBar` as a `button-group` row: Play/Pause (`Play`/`Pause`), Back 10 s (`RotateCcw`), Forward 10 s (`RotateCw`), speed `select` (0.5x, 1x, 2x, 4x), Mute, Snapshot, Mark in, Mark out, Export clip (primary accent button, enabled only when in/out set), Fullscreen. Current time and date in Caption with tabular figures and the site time zone name.

Timeline card (below): zoom `toggle-group` (24h, 12h, 4h, 1h), then the canvas (height 120 + 32 axis). Canvas colors come from tokens:

| Element | Token |
|---------|-------|

## Interaction and Motion Contract

- Transitions 150 ms ease-out for color / opacity / transform on hover, focus, tooltip; 200 ms for sheet / dialog / sidebar width. Nothing else animates. All animation including the REC pulse and skeleton shimmer is removed under `prefers-reduced-motion: reduce`.
- Hover affordances use `--accent` (neutral) surface; pressed state darkens by shadcn defaults. Disabled controls: 50% opacity, `cursor-not-allowed`, still announced via `aria-disabled` when a tooltip explains why.
- Focus: visible 2 px `--ring` ring with 4 px offset on every focusable element; never `outline: none` without a replacement. Dialog / sheet / alert-dialog trap focus and restore it to the trigger (Radix defaults).
- Skip link "Skip to main content" is the first focusable element. Landmarks: `nav aria-label="Primary"`, `header`, `main#main`, `aside` for the camera list.
- Keyboard shortcuts (documented in tooltips with `kbd`): `G` then `L/P/E/G/D` jump to Live / Playback / Events / Gallery / Dashboard; Esc closes maximized tile, sheet and dialogs; `[` toggles sidebar. Shortcuts are disabled while typing in a field.
- Toasts (sonner) are for transient success only: snapshot saved, clip exported, settings saved, code copied. Anything needing action stays inline.
- Data refresh never blanks a screen: TanStack Query keeps previous data and shows a 2 px top-bar progress line while refetching in the background.
- Timestamps display in the site IANA time zone (project rule), 24 h or locale per browser, with the zone abbreviation shown on Playback and Events detail; relative times ("3 min ago") carry the absolute time in `title`.
