# Plan: privacy zone editor - clear save flow and Zone-mode notice

## Problem (owner report: "when I apply it is not working, and the UI is confusing")
Reproduced in a browser against a simulated camera. The save itself reached the camera (POST 200, zone stored), but nothing on screen showed it:
1. The reference picture was never reloaded after a save or delete (one snapshot request for the whole session).
2. After saving, the editor reset to "New zone" and kept the same blue box on top, so the zone looked unsaved and a second Save would create a duplicate.
3. Zones only hide video when privacy mode is `Zone` (`camera_api` SETTINGS_API_GUIDE, "Privacy Mode"). Mode defaults to `None`, lives in a separate card, and nothing linked the two. The mobile app only shows its mask editor when Zone mode is selected.
4. Smaller confusions: a default box shown before the user drew anything, "New zone" in both a dropdown and a button, four percentage fields always visible, a plain click wiping the box, delete required typing the camera name.

The wire format in `camera/onvif/masks.py` was compared with `camera_api` `MaskClient` and `pixelRectToOnvifPolygon`: it matches. No backend API change.

## Tasks
1. `web/src/features/cameras/PrivacyZones.tsx`: rework `ZoneEditor` (reload picture after save/delete/mode change; keep the saved zone selected; zone buttons instead of dropdown; no phantom box; click-safe drawing; saved zones selectable on the picture; exact-position fields folded away; plain delete confirmation; Zone-mode notice with a confirmed "Turn on Zone mode" action that reuses the Privacy tab's cached mode read).
2. `services/sim_camera.py`: simulated snapshot draws masks only in Zone mode, like a real camera.
3. `web/src/features/cameras/features.test.tsx`: update the two existing zone tests, add three (save flow + picture reload, mode notice + turn on, no notice in Zone mode).
